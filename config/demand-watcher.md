# 需要ウォッチャー（検索ワード → 新サービス起案パイプライン）

毎週月曜朝、検索されているワードを自動収集し、
「既存資産で受けられるもの」と「受け皿がない新サービス候補」に仕分けて
GitHub Issue として届けるパイプライン。

```
Googleサジェスト収集（無料・認証不要）
  + Search Console 実クエリ（任意）
        ↓
ノイズ語の除去 → 意図語スコアリング（失敗/意味ない/定着しない…に重み付け）
        ↓
config/assets.yaml の既存資産とマッチング
   ├─ マッチあり → 「該当ページ強化リスト」（SEO追記候補・URL付き）
   └─ マッチなし & スコア閾値超え → Gemini が一枚企画を自動起案
        ↓
reports/demand-YYYY-MM-DD.md 生成 → Issue 起票
```

## ファイル

| パス | 役割 |
|---|---|
| `config/assets.yaml` | **唯一の正**。種ワード・資産レジストリ・スコアリング設定 |
| `scripts/demand_watcher.py` | 収集・スコアリング・レポート生成 |
| `.github/workflows/demand-watcher.yml` | 毎週月曜 7:00 JST に自動実行（手動実行も可） |
| `reports/demand-YYYY-MM-DD.md` | 生成物。botが自動コミットする |

## セットアップ（人間側の作業）

リポジトリの Secrets に設定する（無くても動く。無い場合は自動起案がスキップされる）:

- `GEMINI_API_KEY` … 新サービス候補の一枚企画の自動生成に使用
- `GSC_CREDENTIALS` … Search Console のサービスアカウントJSON（任意）。
  設定すると自サイトの実クエリ（表示回数）もスコアに加算される

手動テスト: Actions タブ →「需要ウォッチャー（週次）」→ Run workflow

## 運用ルール

- **新しい図鑑・ツール・サービスを公開したら `config/assets.yaml` の `assets` に1エントリ追加する。**
  `tags` を書くだけで受け皿として認識される（タグはキーワードへの部分一致で判定）
- レポートに業種違いのワード（ゲームの「1on1」など）が混ざったら、
  `scoring.noise_words` に1語足せば次回から消える
- 「新サービス候補」が3週連続で同じクラスタを出したら着手のサイン
- 「強化リスト」の上位は、該当ページに悩み別セクション・FAQを追記するとSEOが伸びる
  （実例: 1on1図鑑の「こんなときは、どの標本を読むか。」＝ `1on1-zukan.html#gyaku`）

## ローカルでの動作確認

```bash
python3 scripts/demand_watcher.py --seeds 3   # 種ワードを先頭3件に絞って試す
```

`--seeds` を付けないと全種ワードを収集する（Googleサジェストへ数百リクエストするため数分かかる）。
